## Ruptures de compatibilité

Les identités non liées à un tenant ne peuvent plus utiliser les workflows HTTP.
Les exécutions historiques sans tenant doivent être migrées avec attribution
explicite et vérifiée dans `metadata` ET `context.metadata` ; aucune attribution
implicite n'est effectuée. Une création avec un ID existant est refusée (HTTP 422).
Les repositories tiers doivent implémenter un `create` atomique.
Le transport STDIO nécessite l'extra MCP ; il ne transmet pas les headers HTTP.
Son environnement hérité est celui, limité, du SDK plutôt que tout l'environnement hôte.

## Conditions restantes avant release

1. Qualification Python complète acquise sur le commit ci-dessus, y compris
   l'insert-only PostgreSQL. Maintenir ce contrôle sur les prochains changements.
2. Rapprocher le travail S1 local et la branche LLM/éducation sans perdre de correctifs.
3. Compléter l'autorisation du kernel/worker et des outils : le correctif HTTP ne
   constitue pas une isolation RLS ni un audit de toutes les frontières de confiance.
4. Qualifier concurrence du démarrage, atomicité du dispatch, panne/reprise,
   restauration et charge. La reprise de document RAG n'est pas un PRA système.
5. Vérifier le build web et les parcours utilisateur dans un environnement de recette.
6. Compléter le multimodal et GraphRAG seulement selon le périmètre produit accepté.
